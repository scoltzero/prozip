# 07 · 编辑与保存

> 这是 ArcZip 最容易出数据事故、也最能体现工程水平的部分。原版做成"**计划 → 临时包 → 逐项校验 → 原子替换**"。

## 1. 能力边界

| 格式 | 增删改 | 说明 |
|---|---|---|
| ZIP（普通） | ✅ | 原生增量修改；Pro |
| 7Z（普通） | ✅ | 7zz 增量修改；Pro |
| TAR（单文件流） | 仅单文件 | "TAR 编辑仅支持单文件压缩包" |
| ZIP 分卷 / 7Z 分卷 | ❌ | "分卷压缩包暂不支持原位编辑" |
| 拼接 ZIP（多段/SFX） | ❌ | "拼接 ZIP 暂不支持编辑保存" |
| GBK 编码 ZIP | ❌ | "需要兼容旧编码或目录路径的 ZIP 暂不支持编辑保存" |
| 单文件流（gz/xz/lz…） | ❌ | "单文件压缩流不支持归档式编辑" |
| RAR / 其余 | ❌ | 无写入引擎 |

免费版完全没有编辑入口；Pro 激活后才出现"添加文件/删除/重命名/保存"。

## 2. 编辑操作

| 操作 | 入口 | 语义 |
|---|---|---|
| 添加文件 | 工具条/拖入/菜单 | 加入"草稿"，保存后写入 |
| 删除 | 选中 → `Delete` / 右键 | 标记删除，保存后生效 |
| 重命名 | 双击名称 / 右键 | 只改归档内路径 |
| 替换 | 拖入同名文件 | 内容替换，保留路径 |
| 撤销/重做 | `⌘Z` / `⇧⌘Z`，菜单显示具体动作（`撤销 添加文件`） | 操作栈，保存前可回退 |

草稿概念：编辑期间 UI 显示的是"内存中的目标状态"，磁盘上的原包不变；`item.menu.remove_draft_entry`（从待打包内容中移除）与 `remove_archive_entry`（从压缩包移除）是两种不同语义。

## 3. 重命名策略（`ArchiveEntryRenamePolicy`）

校验顺序：

1. 空名 / 只有空白 → 拒绝
2. 含 `/` 或 `\` → 视为路径分隔，不允许在单条目重命名里创建目录（或按目录语义处理，取决于入口）
3. `.` / `..` / 绝对路径 → 拒绝
4. NUL / 控制字符 → 拒绝
5. 与同目录已有条目**大小写不敏感**冲突 → 拒绝或提示
6. 父路径是文件而非目录 → "文件与目录结构冲突"
7. Windows 用途下：非法字符、保留设备名、结尾点/空格 → 提示修复
8. 改名后路径过长 → "ZIP 项目路径过长"

UI："请确认这个项目的新名称"；重命名进行中若有占用 → "此文件正在使用中，请先完成或关闭相关工作区后再重命名"。

## 4. 保存事务

```
1. 生成修改计划（目标条目集 + 每个条目的来源：原包内 / 新文件 / 删除）
2. 建临时工作区 <target>.arczip-update-work-<uuid>/
3. 用引擎写新包：
     - 未变条目：从原包复制（尽量 raw copy，不重新压缩）
     - 新条目：按当前 profile 压缩
     - 删除条目：跳过
4. 逐项校验（见下）
5. 原包备份为回滚文件 → rename 新包覆盖 → 删除备份
6. 失败：恢复备份，删除临时包，报告
```

校验项（原文）：

- 项目数量与计划一致（"增量修改结果的项目数量与计划不一致"）
- 计划内项目齐全（"增量修改结果缺少计划项目："）
- 加密状态一致（"增量修改结果的加密状态不一致："）
- 符号链接目标一致（"增量修改结果的符号链接"…"目标不一致"）
- 大小一致（"增量修改结果大小不一致："）
- 无重复路径（"修改后的压缩包包含重复路径："）

## 5. 源文件变化（并发编辑）

保存前重新 stat 原包（mtime、size、inode）。若与打开时不一致：

> "尚未覆盖原压缩包。可尝试将你的修改合并到最新文件；如有冲突，将停止保存。重新载入会丢失当前未保存的修改。"

三个选项：

| 选项 | 行为 |
|---|---|
| 合并 | 以最新包为基础重放修改；冲突条目停止并列出 |
| 重载 | 丢弃本地修改，重新索引 |
| 取消 | 保持现状，可另存为 |

保存期间目标名被别的进程占用 → "目标名称在压缩期间已被占用，请重新选择处理方式"。

## 6. 未保存状态与关闭

- 标题旁出现圆点（未保存指示）。
- 关闭窗口 / 退出 / 切换 Mini：
  - "Save changes to …?" / "Mini is for browsing. Save or discard your changes to switch."
  - 有任务在跑 → 先完成或取消。
- 保存成功后清除未保存标记，刷新索引（条目 id 可能变化：CRC/大小变了）。

## 7. 编辑与索引的同步

保存完成后**必须重建索引**：路径集合、CRC、大小、压缩大小、加密标记都可能变。原版的 `ArchiveBrowsingSession` 在保存后触发一次完整重扫；未完成前禁用依赖索引的动作。

## 8. 失败与回滚清单

| 失败点 | 结果 |
|---|---|
| 写临时包失败 | 原包不动，删临时目录 |
| 校验失败 | 原包不动，删临时包，报具体不一致项 |
| 备份失败 | 中止，原包不动 |
| 替换失败 | 尝试恢复备份；恢复失败 → `recoveryUncertain`，保留现场 |
| 保存中被取消 | 按上一条回滚 |

> `[实证]` 错误文案、临时目录前缀 `.arczip-update-work-`、校验项；`[推断]` "raw copy 不重新压缩"来自性能文案与 7z 增量行为。
