# 04 · 创建压缩包

## 1. 入口

| 入口 | 行为 |
|---|---|
| `文件 → 创建压缩包` | 新建空工作区（`未命名压缩包.zip`），中间虚线拖放区 |
| 拖文件到 Dock 图标 / 应用图标 | 直接进入创建流，文件已就位 |
| Finder 右键 `压缩为…` | 打开创建面板，预填文件名与内容 |
| Finder 右键 `ArcZip：快速压缩（使用默认设置）` | **不建窗口**，按默认用途/格式/强度直接产出 |
| Box（暂存架）→ 压缩 / 快速压缩 | 用暂存内容创建 |
| 压缩包内 `添加文件` | 编辑已有包（见 07） |

## 2. 创建参数模型

```
CreationProfile {
    purpose:    general | windows | mac | unix | smallest
    format:     zip | sevenZip | tar
    strength:   store | fastest | fast | balanced | maximum
    split:      none | byCount(2…999) | bySize(bytes)
    password:   nil | string  (+ encryptHeaders: Bool)
    preserveMacMetadata: Bool
    processorCount: Int
    windowsNameRepair: Bool
}
```

> `[实证]` 用途/格式/强度/分卷/元数据键均来自设置与文案；`[推断]` 结构体字段名按语义归类。

### 2.1 五种用途（Purpose）

| 用途 | 默认格式 | 语义 | 限制 |
|---|---|---|---|
| 通用分享 General | ZIP | 兼容性与效率平衡；**免费版唯一可用** | — |
| Windows 用户 | 7Z | 跨平台友好；修 Windows 非法文件名 | Pro |
| Mac 之间传递 | ZIP | 保留 macOS 元数据（AppleDouble/扩展属性） | Pro |
| Linux 与服务器 | TAR | 保留 Unix 目录结构与权限 | **仅 TAR**，Pro |
| 尽可能小 Smallest | ZIP 或 7Z | 强度锁定"极限" | **仅 ZIP/7Z**，Pro，强度不可调 |

原文：

> "Linux & Servers supports TAR only."
> "Smallest Size supports ZIP and 7Z only."
> "Smallest Size uses the maximum compression level and cannot be adjusted."

每个用途**独立记住**自己的格式与强度（`archiveCreation.defaultFormat.v2.<purpose>` 之类），切换用途时 UI 跟着换。

### 2.2 压缩强度（5 档）

滑杆 5 个停靠点，文案：

| 档位 | 中文 | 英文 | 行为（推断） |
|---|---|---|---|
| 0 | 仅打包 | Store Only | 不压缩，只封装 |
| 1 | 极速 | Fastest | deflate level 1 / 7z `-mx=1` |
| 2 | 更快 | Faster | level 3 左右 |
| 3 | 均衡 | Balanced | level 5–6（免费版默认） |
| 4 | 极限 | Maximum | level 9 / LZMA2 + 4 GB solid |

- "尽可能小"用途把档位**锁死**在极限。
- TAR 不可调（"TAR only bundles files; the compression level cannot be adjusted"）。
- 7Z 的"极限"写明用 **LZMA2 + 4 GB 固实块**，且"明确无收益内容仍直接存储"。

> `[实证]` 文案与滑杆；`[推断]` 具体 level 数值未在字符串中出现，实现可自定映射，但**语义要对齐**（档位越高越慢越小）。

### 2.3 分卷（Split）

| 项 | 规则 |
|---|---|
| 支持格式 | **仅 ZIP 与 7Z**（"Only ZIP and 7Z support split volumes"） |
| 按数量 | 2–999 卷（"Volume count must be between 2 and 999"） |
| 按大小 | ≥ 1 KB；可选常用值或自定义；单位可切换 |
| 输出 | 数量均分；不足上限只生成一卷；**最后一卷可能较小** |
| 命名 | 数字分卷 `.001…`；ZIP 卷 `.z01…`；RAR 卷 `.r00…`（读） |
| 校验 | 分卷必须连续、无空卷、不超上限、完成后能找到所有卷 |
| 编辑 | 分卷包**不支持原位编辑** |

失败文案（原文）：

- "分卷输出不连续或包含空卷，未发布压缩包"
- "分卷大小超过指定上限，未发布压缩包"
- "分卷压缩完成后未找到输出卷"
- "分卷数量超过支持范围，未发布压缩包"
- "分卷大小与计划不一致"、"每卷大小必须大于零"

### 2.4 密码与加密

| 格式 | 支持 | 说明 |
|---|---|---|
| ZIP | 仅 **ASCII** 密码 | "ZIP 密码字符编码没有统一标准；…创建 ZIP 时密码仅支持 ASCII。中文密码请使用 7Z" |
| 7Z | 任意 Unicode | 支持 AES-256，支持"加密文件名"（header encryption） |
| ZIP AES 写入 | ❌ | "ZIP AES 写入将在授权加密引擎接入后启用" |
| TAR / 单流 | ❌ | 无密码概念 |

交互：创建时密码输入框 + "开启保护"开关 + "保存加密压缩包"；若开启保护但密码为空 → "请设置密码，或关闭密码保护"；两次输入不一致 → "两次输入的密码不一致"。密码可存入密码本（Pro）。

### 2.5 Windows 文件名修复（Pro/Windows 用途）

触发：名称含 `<>:"/\|?*`、保留设备名（CON/PRN/AUX/NUL/COM1…）、结尾点/空格、控制字符。

流程：

1. 扫描出问题项，弹「修正不兼容文件名」：列出原名 → 建议新名，可逐项编辑。
2. 确认后**只改归档内名称**，源文件不动（"Only names inside the archive will change; source files remain unchanged"）。
3. 拒绝不安全路径：绝对路径、`..`、NUL、文件/目录同名冲突（"Unsafe name or path"）。

### 2.6 问题项目（Problem Items）

无法安全加入的条目（无权限、特殊文件、符号链接越界、名称非法）：

- 弹窗列出问题项，可选 **跳过并继续** 或取消。
- 全部都被跳过 → "No selected items can be safely compressed"。
- 原文："These items cannot be archived safely. Skip them to continue."

## 3. 创建事务（最关键的工程点）

原版把"写压缩包"当成数据库事务来做，崩溃后不留半成品。

```
1. prepare    : 在目标目录建临时文件 <name>.arczip-partial-*
2. write      : 引擎写入 + 进度
3. verify     : 结构校验（中央目录/manifest/大小/CRC）
4. publish    : rename 到最终名；若目标已存在，先备份为回滚文件
5. commit     : 删除回滚文件，登记发布完成
```

发布登记表（`archive_publications`，见 `data/publish-registry.sql`）状态机：

```
prepared → backingUp → committed
                     ↘ rollingBack → (恢复成功) / recoveryUncertain
```

启动时会扫描未完成事务：

- `prepared` / `backingUp` 残留 → 回滚：删临时文件、恢复备份。
- `committed` 但临时文件还在 → 清理。
- 无法判定 → `recoveryUncertain`，保留现场并提示。

原始错误文案（说明它真的处理这些情况）：

- "现有压缩包在压缩期间发生了变化，未执行替换"
- "目标名称在压缩期间已被占用，请重新选择处理方式"
- "压缩结果必须在目标文件夹内完成发布"
- "无法安全创建压缩包回滚文件：登记路径已经存在"
- "回滚时发现未登记的目标文件"
- "原压缩包未能完整恢复"

同时，**每个临时产物都在 `temporary_artifacts` 登记**（路径、device/inode、birthtime、size、ownership token、purpose），清理前核对身份：

- purpose 枚举：`shelfResultSaving`、`streamExtraction`、`fontInstallation`、`applicationInstallation`、`finderQuickCompression`、`ownershipUncertain`、`recoveryAvailable`
- 保护规则："临时路径当前身份与登记身份不一致" → 不删；"文件系统在删除后仍报告临时路径存在" → 重试/放弃。

> `[实证]` schema、状态值、错误原文全部来自二进制与运行时 sqlite；`[推断]` 临时文件命名的具体前缀（`-partial-`）未确认，实现可自定。

## 4. 同名冲突与保存

| 场景 | 选项 |
|---|---|
| 目标已存在 | `替换`（覆盖，先备份）/ `同时保留`（自动编号新名称）/ 取消 |
| 原位保存（编辑） | 源文件在保存期间被改动 → 停止保存，提示"合并/重载/放弃" |
| 保存位置 | 默认同目录；记住上次位置（`box.lastSaveDirectory.v1` 等） |
| 跨磁盘 | 允许；先写源盘临时区，再复制到目标盘 |

原文：

- "Replace overwrites the existing archive. Keep Both creates the new archive with a different name."
- "The original archive has not been overwritten. You can try merging your changes into the latest file…"

## 5. 进度与取消

- 进度模型：总字节 + 已完成字节 + 当前条目 + 阶段（`Preparing → Starting → Compressing → Saving safely → Completed`）。
- 多任务：底部/独立进度面板显示 `进行中 / 等待 / 失败` 计数（"Other active tasks: %lld"）。
- 取消：协作式，子进程发 SIGTERM 后等待；超时强杀；已写临时文件按事务回滚。
- 完成后：可选择自动关闭窗口（`extraction/applicationInstallation` 各有独立开关）。

## 6. 默认值与命名

| 项 | 值 |
|---|---|
| 默认文件名 | `Archive.zip` / 中文 `归档.zip` |
| 默认 stem | `Archive` / `归档` |
| 未命名显示 | `Untitled Archive` / `未命名压缩包` |
| 默认格式 | ZIP（每个用途独立记忆） |
| 默认强度 | Balanced（免费）；各用途独立记忆 |
| 默认分卷 | 关闭 |
| 默认保留元数据 | 跟随用途（Mac 用途开启） |
| 压缩线程 | 默认 = 可用核心数；可在高级设置限制（"Maximum CPU Cores"） |

> `[实证]` 文案与默认键；`[推断]` 线程默认值。
