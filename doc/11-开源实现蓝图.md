# 11 · 开源实现蓝图（ProZip）

> 目标：写一个**完全开源**、行为上"够像 ArcZip"的 macOS 压缩包工具。
> 原则：**行为对齐，代码自写，素材自造**。原版的图标、`Assets.car`、本地化文案、品牌名、签名/授权体系都不复制。

## 1. 非目标（先划清）

- 不追求 100% 格式覆盖：先把 ZIP/7Z/TAR/DMG 做扎实，其余按需接 libarchive。
- 不做原版的商业授权/设备席位体系（开源版可以没有 Pro，或只做"赞助"）。
- 不复刻原版的像素级视觉：布局逻辑对齐（三形态、Flow 条、检查器），颜色/字体/图标自定。
- 不逆向原版的私有协议（商业 API 与凭据不在范围内）。

## 3. 引擎协议（关键抽象）

```swift
protocol ArchiveEngine {
    static var capabilities: EngineCapabilities { get }

    func probe(_ url: URL) async throws -> ArchiveDescriptor
    func list(_ url: URL, password: String?, progress: ProgressSink) async throws -> [ArchiveEntry]
    func openMember(_ entry: ArchiveEntry, in url: URL, password: String?,
                    range: Range<Int64>?) async throws -> AsyncThrowingStream<Data, Error>
    func extract(_ entries: [ArchiveEntry], from url: URL, to dir: URL,
                 password: String?, options: ExtractionOptions,
                 progress: ProgressSink) async throws -> ExtractionReport
    func create(sources: [URL], at url: URL, profile: CreationProfile,
                password: String?, progress: ProgressSink) async throws
}

struct EngineCapabilities {
    var read: Set<ArchiveFormat>
    var write: Set<ArchiveFormat>
    var edit: Set<ArchiveFormat>
    var encryptedRead: Bool
    var encryptedWrite: Bool
    var headerEncryption: Bool
    var split: Bool
    var streamingMemberRead: Bool
}
```

`EngineBroker` 负责路由与回退：

```
pick(format, features) -> [Engine]     # 有序候选
try each in order; 记录 fallback reason
```

## 4. 数据模型

```swift
struct ArchiveEntry: Codable, Hashable {
    let id: String            // "<path>#<crc32>#<size>"
    let path: String          // 归档内相对路径
    let type: EntryType       // file/directory/symlink/special
    let uncompressedSize: Int64
    let compressedSize: Int64
    let modifiedAt: Date      // 存库时转 Apple epoch
    let permissions: UInt16
    let crc32: UInt32
    let isEncrypted: Bool
    let isAuxiliary: Bool
    let isDiskImageBackground: Bool
    let isApplicationsShortcut: Bool
}

struct CreationProfile {
    var purpose: Purpose      // general/windows/mac/unix/smallest
    var format: ArchiveFormat // zip/sevenZip/tar
    var strength: Strength    // store/fastest/fast/balanced/maximum
    var split: SplitPlan?     // .byCount / .bySize
    var password: String?
    var encryptHeaders: Bool
    var preserveMacMetadata: Bool
    var processorCount: Int
    var repairWindowsNames: Bool
}
```

索引 schema 直接沿用本文档 [02](02-浏览与索引.md) 的两张表（字段语义相同即可，表名可自定）。**建议保留**：

- `entries` + `directory_nodes` 双表（列表查询 O(log n)，翻目录不用建树）
- `id = path#crc#size`（同名不同版本可区分）
- `directory_nodes` 的 upsert 只允许真实目录覆盖虚拟目录

## 5. 并发模型

| 关注点 | 方案 |
|---|---|
| UI 状态 | `@MainActor` + Observation（或 TCA/Reducer） |
| 索引 | 单独 actor，写 SQLite 用串行队列 + 事务 |
| 引擎调用 | 每个任务一个 `Task`，通过 `AsyncStream` 汇报进度 |
| 子进程 | `Process` + 两个 `Pipe`，逐行读、限速、可取消（SIGTERM→SIGKILL） |
| 内存 | 成员读取必须"范围读 + 背压"：`AsyncThrowingStream` 带 `maxInFlight` |
| 崩溃隔离 | 引擎跑在 XPC 服务里；主 app 只拿结果 |
| 取消 | `Task.cancel()` → 引擎协作检查 → 清理临时文件 |

原版的教训：`Too many active member reads`、`Member output exceeds budget` —— 并发读成员必须有配额，否则大包会把内存打爆。

## 6. 存储布局（建议）

```
~/Library/Caches/<bundle-id>/
├── Sessions/<pid>-<uuid>/Indexes/index-<uuid>.sqlite
├── Sessions/<pid>-<uuid>/Previews/window-<uuid>/
├── Mounts/
└── Registry/artifacts.sqlite        # 临时产物 + 发布事务
```

`Registry` 表结构照抄 [04](04-创建压缩包.md) 的两个表；这是"能强杀进程"的底座。

## 9. 依赖与许可（建议）

| 依赖 | 版本 | 用途 | 许可 | 注意 |
|---|---|---|---|---|
| ZIPFoundation | 0.9.20 | ZIP 容器读写基础 | MIT | 与原版同款，可放心用 |
| libdeflate | 1.26 | raw Deflate 编码（ZIP 写） | MIT | 只取 Deflate 子集；比 zlib 快 |
| 7-Zip `7zz` | 26.04 | 7z/RAR/宽格式/增量修改 | **LGPL-2.1 + unRAR 限制** | 独立进程调用；RAR 解压受 unRAR 约束，不能用于重造 RAR 压缩器 |
| 7-Zip LZMA2 C 编码子集 | 26.04 | 压缩收益探测（小样本打分） | Public Domain | 原版静态链入；不含 unRAR 代码 |
| libarchive（系统） | 系统版 | tar/单流/老格式 | BSD-2 | 系统自带，无需打包 |
| ds_store / mac_alias | — | 读 `.DS_Store`（DMG 布局） | MIT | 原版是"改编"而非直接依赖，需自行实现有界解析 |
| Sparkle | 2.9.4 | 更新 | MIT | 自建 appcast 与 EdDSA 密钥 |
| SQLite | 系统版 | 索引 | Public Domain | 系统自带 |
| Inter Bold | 3.019 | UI 字体（Pro 徽标） | SIL OFL 1.1 | 可换成系统字体 |
| VariableBlur | — | 渐进模糊（UI） | MIT | 非核心，可不用 |

**不要**打包原版的 `7zz` 二进制而不附许可文本；不要把 RAR 解压代码静态链进 GPL 不兼容的项目（用独立进程最稳）。

## 10. 清洁室边界

可以做：
- 观察行为、记录 UI 文案的**语义**、复现交互流程
- 读文件格式规范、用公开库
- 自己写所有代码与测试

不要做：
- 复制原版二进制、`Assets.car`、`7zz`、`libdeflate` 编译产物、字体、图片
- 逐字复制 `Localizable.strings`（文案有版权）；请重写自己的措辞
- 使用 `com.maczhang.ArcZip` 的 bundle id、App Group、Keychain group
- 复用其签名、授权服务、appcast

## 11. 风险清单

| 风险 | 缓解 |
|---|---|
| ZIP 编码（GBK/CP437）判断错 | 先 flag 11，再启发式；编辑时拒绝不确定项 |
| 大包内存爆 | 强制范围读 + 背压 + 预算 |
| 解压路径穿越 | 计划阶段统一规范化 + 符号链接检查 |
| 保存覆盖用户文件 | 事务 + 备份 + 源变化检测 |
| 7zz 输出协议变化 | 版本探测 + 解析容错 + 退出码兜底 |
| 分卷命名不统一 | 家族识别（`.001`/`.z01`/`.r00`/`.partN.rar`） |
| 商业层缺失导致功能残缺 | 开源版直接全功能，或做"捐赠解锁"但不做设备席位 |
