# 02 · 浏览与目录索引

这是 ArcZip 的核心机制：**打开压缩包 = 建一个本地索引库**，之后所有 UI 操作都查库，不重复扫压缩包。

## 1. 会话目录布局

```
~/Library/Caches/com.maczhang.ArcZip/
├── Temporary/
│   ├── Sessions/
│   │   └── <pid>-<UUID>/
│   │       ├── Indexes/
│   │       │   ├── index-<UUID>.sqlite
│   │       │   └── index-<UUID>.sqlite-wal / -shm
│   │       └── Previews/
│   │           └── window-<UUID>/…
│   ├── DiskImageMounts/
│   └── temporary-artifacts.sqlite          # 全局临时文件登记表（见 04/05）
├── ApplicationLaunchHandoffs/              # DMG 内应用启动交接
└── InstallerHandoffs/                      # 安装器交接
```

- 目录名 `<pid>-<UUID>`：pid 用于判断会话是否还活着；进程退出后整目录成为可清理垃圾。
- 每个窗口/压缩包一个 `index-<UUID>.sqlite`；分卷包按“第一卷 + 同族卷”合成一个会话 `[推断]`。
- `Previews/window-<UUID>/` 放预览物化文件（Quick Look/缩略图源），有独立预算与上限。

> `[实证]` 实际磁盘结构；`[实证]` 会话路径也在助手脚本里被读取验证。

## 2. 索引 Schema（原文）

```sql
PRAGMA journal_mode=WAL;
PRAGMA synchronous=FULL;          -- 全局登记表使用
PRAGMA wal_autocheckpoint=100;

CREATE TABLE IF NOT EXISTS entries (
    id TEXT PRIMARY KEY,
    path TEXT NOT NULL,
    is_auxiliary INTEGER NOT NULL,
    is_disk_image_background INTEGER NOT NULL,
    is_dmg_applications_shortcut INTEGER NOT NULL,
    payload BLOB NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_entries_path ON entries(path COLLATE NOCASE);
CREATE INDEX IF NOT EXISTS idx_entries_path_exact ON entries(path COLLATE BINARY);

CREATE TABLE IF NOT EXISTS directory_nodes (
    canonical_path TEXT PRIMARY KEY,
    parent_path TEXT NOT NULL,
    sort_name TEXT NOT NULL,
    is_directory INTEGER NOT NULL,
    is_virtual INTEGER NOT NULL,
    is_auxiliary INTEGER NOT NULL,
    is_disk_image_background INTEGER NOT NULL,
    is_dmg_applications_shortcut INTEGER NOT NULL,
    payload BLOB NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_directory_nodes_parent_exact
    ON directory_nodes(parent_path COLLATE BINARY, is_directory DESC, sort_name COLLATE NOCASE);
```

> `[实证]` 从 `__cstring` 0xc54e50–0xc558c0 提取；`[实证]` 运行时库 `.schema` 一致。

### 2.1 为什么有两张表

- `entries`：**扁平全量索引**，一条一个归档条目，用于搜索、批量操作、跨目录定位。
- `directory_nodes`：**预排序的目录视图**，每个"父目录"一行，含 `sort_name`，让 UI 翻目录只做一次 `WHERE parent_path = ? ORDER BY …`，不用在内存里建树。

写入流程（原文）：

```sql
BEGIN IMMEDIATE TRANSACTION;
DELETE FROM entries;
DELETE FROM directory_nodes;
INSERT OR REPLACE INTO entries(id,path,is_auxiliary,is_disk_image_background,is_dmg_applications_shortcut,payload) VALUES(?,?,?,?,?,?);
INSERT INTO directory_nodes(...) VALUES(...)
ON CONFLICT(canonical_path) DO UPDATE SET ... WHERE excluded.is_virtual = 0;
```

要点：

- 整包重建用**一个大事务**，先清空再灌，避免"半包"状态。
- `directory_nodes` 的 upsert 带 `WHERE excluded.is_virtual = 0`：**真实目录优先于虚拟目录**，虚拟目录（分卷聚合、DMG 背景等）不会覆盖真实节点。
- 翻页查询固定 `LIMIT ? OFFSET ?`；计数单独一条 `SELECT COUNT(*)`。

### 2.2 payload 字段（JSON，`[实证]` 解出）

```json
{
  "id": "readme.txt#958094898#13",
  "path": "readme.txt",
  "type": "file",                  // file | directory | symlink | …
  "modifiedAt": 815987118,         // 秒，2001-01-01 起算（Apple epoch）
  "permissions": 420,              // 0644 = 420，0755 = 493
  "uncompressedSize": 13,
  "compressedSize": 13,
  "encrypted": false,
  "checksum": 958094898            // 目录里文件是 CRC32；目录为 0
}
```

- **条目 id 约定**：`path#checksum#size`。它同时承担"同名不同版本"的区分；目录用 `path/#0#0`。
- `modifiedAt` 用 Apple epoch（2001 起），不是 Unix 时间戳，跨端转换时注意。
- `permissions` 是 POSIX mode 的十进制；ZIP 里没有 Unix 属性时给默认 0644/0755。
- `checksum` 用于快速识别"同名但内容不同"和"解包后校验"。

> `[实证]` 直接读 sqlite payload 得到；目录节点 payload 与 entries 完全相同，便于一行渲染。

## 3. 索引阶段与能力门

| 阶段 | UI 文案 | 可用 | 不可用 |
|---|---|---|---|
| `preliminary` | "正在核对压缩包目录 / 正在建立文件索引" | 浏览、全部解压 | 搜索、预览、拖出、解压所选、编辑 |
| `ready` | —— | 全部 | —— |
| `failed` | "无法读取压缩包 / 压缩包无效或已损坏" | 重试/关闭 | 全部 |

对应原文：

> "可以浏览和全部解压。文件列表读取完成后可搜索、预览、拖出或解压所选文件。"
> "请等待文件列表读取完成，再%@。"
> "完整文件索引完成后即可拖出或解压"

实现建议：索引任务与首屏任务分开。首屏只读中央目录（或 7z 的 header），先把树画出来；完整索引（含每条的 CRC/size/属性）在后台补齐，通过 `ArchiveReadSessionProgressPayload` 推阶段与计数。

> `[实证]` 文案；`[推断]` 阶段划分来自 `ArchiveReadSessionProgressPayload.Phase` 与上述提示语。

## 4. 排序与"进入目录"

排序规则（SQL + 内存一致）：

1. `is_directory DESC`（目录在前）
2. `sort_name COLLATE NOCASE`（大小写不敏感的名字序）
3. 同名再按原始字节序兜底

> 注意：**不是** Finder 的 `localizedStandardCompare`。中文/数字混排时结果与 Finder 可能不同，这是行为差异点，重实现时要么对齐 NOCASE，要么明确改成 localized 排序（会与行映射假设冲突）。

"进入目录"语义：

- 双击目录 → 列表整体替换为该目录内容，**面包屑加一级**，所有行 level 仍为 0。
- 因此"第 N 行 → 归档条目"必须用「当前目录 + 排序后的第 N 项」重建，不能拿全局 rowid 偏移。
- 返回/上一级/前进 维护一个路径栈（`ArchiveBrowserKeyboardNavigation`）。

> `[实证]` 交互实测；`[实证]` 排序 SQL；`[推断]` 路径栈来自类型命名。

## 5. 搜索（Pro）

- SQL：`path LIKE ? ESCAPE '\'`，配合 `idx_entries_path`（NOCASE）。
- 输入防抖后查询，`LIMIT/OFFSET` 分页；结果仍是列表行，可直接预览/解压。
- 免费版点搜索 → Pro 弹窗（"包内搜索属于 ArcZip Pro"）。

实现提示：条目量很大时 `LIKE '%kw%'` 会全表扫。原版就接受这个代价（没有 FTS5 表）。若要更好，可加 FTS5 虚表，但注意与 `entries` 的同步成本。

> `[实证]` SQL 与文案；`[推断]` 防抖/分页来自 `FlowActionRouter` 与查询形态。

## 6. 预览与缩略图

| 能力 | 机制 |
|---|---|
| 列表图标 | 按扩展名映射系统图标（`NSWorkspace.icon(forFileType:)` 类） |
| 检查器大图 | 解出条目到 `Previews/window-*/` 临时文件，交给 Quick Look 缩略图 |
| 空格预览 | 同样物化后 `QLPreviewPanel` |
| 悬浮预览（Pro） | 指针停留触发；图片/PDF/文本用缩略图，音视频用 AVFoundation 播放 |
| 文件夹预览 | 取前 N 个成员拼"缩略图堆叠" |

安全与预算（原文）：

- "缩略图批次目标必须是本地目录"
- "缩略图批次只允许普通文件"、"包含过多项目"、"预计解压量过大"、"实际写入量超过安全限制"
- "缩略图源文件过大："
- "Quick Look 缩略图提取内容超过安全上限"
- 悬浮视频上限可选 10 MB / 50 MB / 100 MB / 500 MB / 1 GB / 2 GB（**按解压后大小**，含上限）

> `[实证]` 文案与设置项；`[推断]` 具体阈值常量未静态确认，实现时自定义即可，但**必须存在**上限。

## 7. 拖出（file promise）

- 拖拽开始时只承诺文件名与大小，不立即解包；落到目标后由 `FilePromiseTaskRegistry` 调度真实解包。
- 失败可重试；任务与窗口生命周期绑定，关窗前要求完成或取消。
- 支持多选、目录（递归展开）。

> `[推断]` 拖放细节由 `PromiseDragSource`、`FilePromiseTaskRegistry`、`FileDropPayload` 类型与"文件已就绪"文案推得。

## 8. 辅助项目与过滤

被标记为 `is_auxiliary` 的条目：

- `__MACOSX/`、`._*`（AppleDouble）
- `.DS_Store`、`Thumbs.db`、`desktop.ini`
- 卷索引（`.Spotlight-V100`、`.fseventsd`、`.Trashes` 等）
- DMG 布局隐藏文件与 `Applications` 替身（另有 `is_dmg_applications_shortcut` 标记）

规则：

- 列表默认隐藏，开关 `showsAuxiliaryEntries.v1` 控制显示。
- 解压默认过滤，但**显式选中的辅助文件/文件夹必须保留**，App 包内部文件也保留。
- `.gitignore`、`.env` 等配置类点文件**不算**辅助文件，不过滤。

> `[实证]` 设置页帮助原文与列名。

## 9. 多窗口与重复打开

- 同一路径已打开：提示"已在另一个窗口打开，请在那个窗口中操作"，并把该窗口前置。
- 每个窗口独立索引库、独立临时目录；删除窗口时清理自己的 session 目录。
- 退出时若有未完成索引/解压：走 `ApplicationTerminationOrchestrator`，提示或延迟退出。

## 10. 错误语义（浏览相关）

| 场景 | 文案 |
|---|---|
| 包损坏 | `压缩包无效或已损坏：` |
| 目录与内容不一致 | `压缩包内容与识别格式不一致` |
| 条目读取失败 | `无法读取文件。压缩包返回的数据与目录索引不一致。…` |
| 目录项过多/输出过大 | `归档辅助进程输出超过 16 MiB 上限，任务已停止` |
| 行不可用 | `项目不存在或无法访问` |

错误弹窗统一带：`错误详情`（文件路径、错误代码、请求编码）、`源压缩包未被修改`。

> `[实证]` 全部为二进制/本地化原文。
