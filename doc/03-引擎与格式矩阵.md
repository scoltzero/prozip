# 03 · 引擎与格式矩阵

ArcZip 不是一个引擎打天下，而是**四层引擎 + 路由**。理解这层分工，开源版才能既覆盖格式又不被单一库绑死。

## 1. 引擎分层

| 层 | 实现 | 负责 | 关键特征 |
|---|---|---|---|
| L1 原生 ZIP | `NativeStreamingZIPWriter`（自研外壳：**ZIPFoundation 0.9.20** 管容器 + **libdeflate 1.26** 写 raw Deflate；收益探测用 **7-Zip 公有领域 LZMA2 编码子集**） | ZIP 创建、ZIP 浏览、ZIP 条目流式读取、增量修改 | 流式、有 manifest、写后结构校验、Deflate 收益探测 |
| L2 内置 7-Zip | `Contents/Resources/7zz`（**7-Zip 26.04 arm64**） | 7Z 创建/读取/增量修改；RAR 读取；宽格式（ISO/UDF、WIM、DMG 兼容、NSIS 等） | 子进程 + 行协议进度；密码走安全管道 |
| L3 系统 libarchive | `BSDTarEngine`（系统 `libarchive`，错误前缀 ` bsdtar `） | TAR 家族、gz/bz2/xz/lzma 单流、cpio、ar、xar、rpm、cab、lha、arj 等兼容格式 | 进程内/系统库，`--no-mac-metadata`、`--no-same-permissions`、`hdrcharset` |
| L4 磁盘映像 | `DiskImageEngine`（`hdiutil`） | DMG/ISO 只读挂载、卷内浏览、应用/字体安装、拖放导出 | `hdiutil attach` 进度解析、SLA 许可、只读会话 |
| 专用 | `LzipEngine` | `.lz` 单文件流 | 独立解析器（libarchive 不一定带 lzip） |

> `[实证]` 类型名、源码文件名（`ArchiveEngines/NativeStreamingZIPWriter.swift`、`ZIPDeflatePolicy.swift`）、`7zz --help` 版本、错误原文、`THIRD_PARTY_NOTICES.md` 的组件与许可声明。
> `[实证]` Deflate 编码器是 **libdeflate 1.26**（"includes the raw Deflate compression subset of libdeflate"），不是 zlib / `Compression.framework`。

## 2. 路由规则（从错误文案反推）

```
打开/解压：
  DMG/ISO                         → L4（挂载）；失败回退 L3 解析（ISO 回退引擎）
  ZIP/ZIPX（非分卷、非加密、非加密头）
                                  → L1
  ZIP 分卷 / 加密 ZIP / 特殊方法   → L2 或 L3（"此 ZIP 的压缩方法或目录元数据需要使用兼容引擎"）
  7Z / RAR / 其他宽格式            → L2
  TAR 家族 / 单文件流 / 老格式      → L3
  .lz                             → LzipEngine

创建：
  ZIP（非加密、非分卷）            → L1
  ZIP 加密 / ZIP 分卷              → L2（7zz）
  7Z（含加密、分卷、固实）          → L2
  TAR                             → L3（仅打包）

编辑保存：
  ZIP / 7Z 非分卷                  → L2 增量修改
  TAR 单文件                       → L3
  其余                             → 不支持（"原生增量修改仅支持 ZIP 和 7Z"）
```

判定顺序很重要：**先看容器特征（分卷/加密/方法），再看扩展名**。原文里多次出现"路由格式与已验证目录不一致"、"解压请求格式与已验证目录不一致"，说明路由结果要与索引里记录的格式做二次校验。

## 3. 格式能力矩阵

完整表见 `data/formats.tsv`。摘要：

| 格式 | 浏览 | 解压 | 创建 | 编辑 | 加密读 | 加密写 | 分卷 |
|---|---|---|---|---|---|---|---|
| ZIP / ZIPX | ✅ | ✅ | ✅（免费） | ✅ | ✅（ZipCrypto） | ❌ `[上限]` | ✅ 读/写 |
| 7Z | ✅ | ✅ | ✅（Pro） | ✅ | ✅ | ✅（AES-256，含加密头） | ✅ |
| RAR / CBR | ✅ | ✅ | ❌ | ❌ | ✅ | ❌ | ✅ 读（`.partN.rar`/`.rNN`） |
| TAR | ✅ | ✅ | ✅（Pro，仅打包） | 仅单文件 | ❌ | ❌ | ❌ |
| TAR.GZ / TGZ | ✅ | ✅ | ✅（gz） | ❌ | ❌ | ❌ | ❌ |
| TAR.BZ2 / TBZ2 | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| TAR.XZ / TXZ | ✅ | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| GZ / BZ2 / XZ / LZMA | ✅ | ✅ | ✅（单流） | ❌ | ❌ | ❌ | ❌ |
| LZ（lzip） | ✅ | ✅ | ❌ `[上限]` | ❌ | ❌ | ❌ | ❌ |
| DMG | ✅ 挂载 | ✅ 导出 | ❌ | ❌ | ✅（加密 DMG） | ❌ | — |
| ISO | ✅ 挂载 | ✅（挂载→复制） | ❌ | ❌ | ❌ | ❌ | — |
| CAB / CPIO / ARJ / LHA / XAR / RPM | ✅ | ✅ | ❌ | ❌ | 部分 | ❌ | ❌ |
| MSI / PKG / JAR / APK / SPK / EXE / SWF | ✅ 当容器读 | ✅ | ❌ | ❌ | — | ❌ | ❌ |

说明：

- MSI/PKG/JAR/APK/SPK/EXE/SWF 本质是"能当容器打开的软件包"，ArcZip 只做**预览与解压**，不执行安装逻辑（PKG 默认仍交系统安装器）。
- `zipx` 的"x"只是扩展名，真实方法可能是 deflate/bzip2/lzma/ppmd；方法不支持时回退 L2。
- RAR 只读：没有 RAR 写入器，也没有 RAR 授权库。
- 数字分卷 `.001…999`、ZIP 分卷 `.z01…z99`、RAR 分卷 `.r00…r99` 都注册了 UTI；`.001` 这种要**优先按同族第一卷**打开，而不是单卷。

> `[实证]` Info.plist 文档类型/UTI、二进制格式描述串、错误文案；`[推断]` 个别"✅"来自引擎能力与文案的组合，如 RPM 有"无法读取 RPM 的有效载荷目录"。

## 4. 7-Zip 调用约定

```bash
7zz a -t7z  <out.7z>  <inputs...>     # 创建
7zz l -slt <archive>                  # 目录（机器可读）
7zz x      <archive> -o<dir>          # 解压
7zz d/u    <archive> <entries...>     # 删除/更新（增量修改）
```

关键点：

1. **密码不进 argv**。真实密码通过管道/fd 传给子进程，命令行只放占位符 `-p__ARCZIP_NO_PASSWORD__`。原文："为避免密码暴露在进程参数中，预览版不通过 bsdtar 创建加密包"。
2. **进度靠解析 stdout**：`SevenZipProgressParser` / `SevenZipExtractionProgressParser`，按行解析百分比与当前文件；`phase=7zz_first_progress elapsed_ms=…` 是埋点。
3. **输出上限**：stdout 单行 4 MiB、stderr 4 MiB、总输出 16 MiB，超限即杀进程（"归档辅助进程输出超过 16 MiB 上限，任务已停止"）。
4. **退出码语义**：0 成功、1 警告、2 致命、7 命令行错误、8 内存不足、255 用户中断。原版把 1 当"警告"，并**拒绝发布可能不完整的结果**（"7-Zip 创建归档时报告了警告，未发布可能不完整的压缩包"）。
5. **固实参数**：最大强度用 LZMA2 + 4 GB solid block（文案原文："Maximum LZMA2 with 4 GB solid blocks"）。

> `[实证]` 占位符、上限、警告文案；`[推断]` 具体 switch 组合（`-mx`、`-ms`）未在字符串中出现，属于运行时拼接。

## 5. libarchive 约定

- 直接调用系统 libarchive（错误串带 ` bsdtar ` 前缀），不依赖用户安装。
- 关键选项：
  - `--no-mac-metadata`：不写 `__MACOSX`/AppleDouble
  - `--no-same-permissions`：不还原权限（避免奇怪 mode）
  - `--files-from`：按清单精确解压（防 shell 转义问题）
  - `zip:hdrcharset=CP437` / `zip:hdrcharset=<detected>`：处理无 UTF-8 标志的旧 ZIP 文件名
  - `zip:!mac-ext`：忽略 macOS 扩展字段
- 编码策略：先看 ZIP general purpose bit 11（UTF-8 flag）；没有则按 CP437 解码，再尝试 GBK/Big5 启发式；**能显示但不可无损回写**时，编辑功能直接拒绝（见"GBK ZIP 不可编辑"）。
- 单文件流（gz/bz2/xz/lzma/lz）暴露为"一个虚拟文件"，文件名由容器内记录或去扩展名推得；RPM 的内层 payload 需要单独解一层。

> `[实证]` 选项串与编码错误文案；`[推断]` 具体 API 调用路径。

## 6. 原生 ZIP writer 的写出策略

这是最值得抄的部分：**写完不算完，要证明写对了**。

1. **计划（manifest）**：先算 `CreationManifest`：条目、方法（Store/Deflate）、大小、CRC。
2. **收益探测**：对每个条目先压一小段（`CompressionBodyProbe`，有 `sampleBudgetBytes` 预算），估算压缩率；"明确无收益"的直接 Store。
   - 探测用的不是 libdeflate，而是**静态链入的 7-Zip 26.04 公有领域 C LZMA2 编码器子集**（notices 原文：`for bounded in-process compression sampling`，且明确 `No unRAR code is included`）。
   - 这样能用"更接近最终 7z 效果"的编码器打分，但只在小样本上跑，成本可控。
   - 原文："ZIP Deflate 项目没有净收益："
   - 原文："ZIP 方法验证不一致，应为 Store"
3. **流式写**：`ZIPOutputSink` + `CompressionQueue` + `ReadyPayloadQueue`，多 worker 并行压、单线程按序写，避免内存爆。
4. **结构校验**：写完后重新读中央目录，逐项核对
   - 项目数（"ZIP 中央目录项目数不一致"）
   - 计划外项目（"ZIP 结构验证发现计划外项目"）
   - 类型/大小/方法（"…项目类型不一致"、"…项目大小不一致"）
   - 与 manifest 的一致性（"ZIP 结构验证与 Creation Manifest 不一致"）
5. **原子发布**：临时文件 → `fsync` → rename 到目标；失败回滚。

> `[实证]` 全部为错误原文与类型名；`[推断]` 并行度由 `maxConcurrentCompressionWorkers` 控制。

## 7. 明确的能力上限（照抄可省事）

| 上限 | 证据 |
|---|---|
| 不写加密 ZIP | "ZIP AES 写入将在授权加密引擎接入后启用；不会回退到泄露命令行密码的实现" |
| 不解密 ZIP AES 预览 | "此预览版尚未接入 ZIP AES 解密" |
| 不编辑 GBK ZIP | "自动识别为 GBK 的 ZIP 暂不支持编辑保存" |
| 不编辑拼接/分卷 ZIP | "拼接 ZIP 暂不支持编辑保存"、"分卷压缩包暂不支持原位编辑" |
| 单文件流不可编辑 | "单文件压缩流不支持归档式编辑" |
| RAR 无写入 | 无相关引擎 |
| Lzip 无创建 | "Lzip 创建尚未开放" |
| ISO 回退受限 | "ISO 回退引擎不支持应用程序提取"、"ISO 回退引擎不支持提取" |
| ZIP 密码限 ASCII | "创建 ZIP 时密码仅支持 ASCII。中文密码请使用 7Z" |

> 这些不是"实现不到位"，而是**刻意的安全/兼容取舍**：宁可不做，也不把密码放到 argv、不产出跨平台打不开的包。开源版可以做得更多，但要知道原版为什么停在这。

## 8. 引擎相关的错误词典

见 `data/engine-strings.txt`，按主题分组：

- 打开/读取：`无法读取压缩包`、`压缩包数据损坏或格式不正确`、`分卷不完整或压缩包头损坏`
- 密码：`cannot open encrypted archive. wrong password?`、`headers error in encrypted archive`、`data error in encrypted file`
- 安全：`dangerous link path was ignored`、`ZIP 符号链接目标超出提取范围`、`归档路径包含父目录跳转（..）`
- 预算：`Member output exceeds budget`、`Too many active member reads`、`Member metadata is too large`
- 兼容：`unsupported method`、`系统 libarchive 缺少压缩流解码器`、`此 ZIP 的压缩方法或目录元数据需要使用兼容引擎`
